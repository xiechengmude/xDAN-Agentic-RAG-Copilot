本知识库详细介绍了智信贷款平台的系统架构与核心流程，涵盖授信、借款、还款、信息同步等环节的业务逻辑及系统交互机制

# 平台说明
平台名称：智信贷款平台
功能：连接用户和机构，为用户推荐机构，为机构提供用户流量并收取分润费用
说明：
 - 智信贷款平台是奇富借条下的一个子产品，奇富借条包含一个自营产品"借条"和多个子产品：如智信，微零花，大额贷等。
 - 智信平台下面又分为智信Z模式和辅助模式，这里只解释智信Z模式的具体逻辑（注意智信Z的扣款模式下又包含一个辅助扣款模式，与这里的辅助模式不是一回事）
## 概念
1. 奇富借条：这是一个APP的名称，属于奇富科技公司
2. 机构：可能是一个银行，也可能是一家消金公司、融担公司等，也称为资金方、合作方等。他们为用户提供放款的资金。

# 系统说明
1. ice-crp: 路由系统，主要负责路由的逻辑
 - 授信路由：从平台所有的合作机构中选择出最适合用户的机构让用户发起授信
 - 借款路由：从用户所有授信成功的机构中选择出最优质的机构让用户发起借款
2. ice-pfs-app: 产品流程系统，主要负责用户申请相关的流程，如：
 - 用户授信申请流程：需要判断用户要填写哪些授信信息，是否要绑卡等。如果用户中途退出申请，还要记录状态，以便用户再次进来时可以继续申请
 - 授信机构交互流程：需要将用户的授信信息提交给机构，并定时轮询机构的授信结果，或接收机构的授信结果通知
 - 用户借款申请流程：同样的需要判断用户要填写哪些借款信息，是否需要绑卡，是否需要刷脸验证等。但是不需要记录状态，因为用户每次来借款都是从头开始申请的
 - 借款机构交互流程：同样的，需要将用户借款信息与机构交互，并定时轮询借款结果或者接收机构借款结果通知
 - 还款申请流程：需要判断哪些借款要在前端提示用户需要还款，转发用户的还款试算，还款申请信息到ice-core-app
3. ice-partner-app: 
 - 主要负责补充机构的授信、借款申请信息，兼容机构的差异，然后转发内部请求给ice-gws-app
 - 保存了机构所有的配置信息，如接口地址，公钥，绑卡模式等，使用SDK的方式经机构服务使用，如，ice-gws-app通过SDK获取到机构的接口地址和密钥信息
4. ice-gws-app:
 - 主要与机构交互，把内部请求转给发机构，主要负责加密加签，并对机构的数据验签解密。整体起到一个将加密的http接口转成内部的非加密的dubbo接口的能力
5. ice-gws-web:
 - 提供http接口给机构请求，将请求验签解密后转发给内部系统，然后将内部系统的响应加密加签再响应给机构
6. ice-core-app:
 - 负责记录用户授信成功的额度信息、放款成功的借款及还款计划信息，负责处理用户的还款流程，借据信息同步、额度同步等

# 授信流程

## 用户申请流程

用户登录APP ➔ 授信路由流程 ➔ 用户填写信息 ➔ 同意协议 ➔ 绑定银行卡(可选) ➔ 人脸验证 ➔ 提交申请到ice-pfs-app ➔ 进入授信机构交互流程

### 授信路由流程
ice-crp-app
路由流程是指从平台内部的100+机构中选择一部分机构给用户展示，让用户选择授信。
在路由流程中，会判断机构是否满足可授信的条件，大概包含以下一些校验：
 - 该机构是否在维护时间段
 - 该机构当天是否达到了授信上限，比如一家机构一天只接受1000笔授信，则达到这个量后就不再路由出来
 - 该机构是否支持用户的银行卡
 - 该机构撞库接口是否返回可申请
以上非所有规则
 
说明：撞库是机构提供的一个接口，在该接口中，智信会把用户信息的md5值发送给机构，机构判断该用户是否从其他APP申请过了，如果已经申请过，则会返回不可申请状态

### 绑定银行卡流程

在智信平台有两类机构：
 - 机构绑卡扣款模式机构：这类机构用户绑卡时需要将银行卡绑定到他们平台内部，后续还款时他们自行扣款
 - 辅助扣款模式机构：这类机构用户绑卡时需要绑定在借条内部，还款时由智信负责选择扣款渠道及协议号，在还款申请接口传给机构，机构拿着去支付渠道扣款

对于`机构绑卡扣款模式`，用户绑卡时需要调用机构的发送验证码接口`applyCertification`和校验验证码接口`verifyCode`，两个接口的调用链路都是：
 - ice-pfs-app调用ice-partner-app提供的dubbo接口，接口名为`applyCertification`/`verifyCode`
 - ice-partner-app收到请求后将请求转发到ice-gws-app提供的同名的dubbo接口中
 - ice-gws-app收到请求后将请求参数加密加签，并转发到机构提供的http接口中
 - ice-gws-app收到机构响应后对响应参数验签解密后返回给ice-partner-app
 - ice-partner-app将响应参数返回给ice-pfs-app

对于`辅助扣款模式`，用户绑卡时会将银行卡绑定到借条中，因此不需要调用机构的接口，而是会调用pcs的接口（pcs是借条统一处理支付的微服务）。

#### 概念说明
1. 支付渠道：又称通道、渠道，指的是通联、宝付、易宝等持有支付牌照的公司，智信或者机构需要通过支付渠道去给用户扣款
2. 协议号：指的是支付协议号，用户通过借条或机构在支付渠道绑卡成功后，支付渠道记录该用户的支付协议号，后续扣款需要使用该协议号批扣

## 授信机构交互流程

用户提交申请到ice-pfs-app后，就进入授信机构交互流程，接下来ice-pfs-app会把申请信息提交到机构中，并定时轮询授信结果，以下为流程详细说明：

授信提交流程：
1. ice-pfs-app 定时查询数据库中状态为`未提交`的记录，并对每一笔授信都调用ice-partner-app提供的applyCredit接口(dubbo接口)
2. ice-partner-app 收到ice-pfs-app调用后，会检查是否有需要补充的授信信息，然后将补充后的请求转发到ice-gws-app的applyCredit接口(dubbo接口)
3. ice-gws-app 收到ice-partner-app调用后，会将请求参数加密加签，并调用机构提供的applyCredit接口(http接口)
4. ice-gws-app收到机构响应后，解密机构的响应内容，并返回到ice-partner-app
5. ice-partner-app再将响应返回给ice-pfs-app
6. ice-pfs-app根据机构响应的状态调整数据库中授信记录的状态：如果机构返回接收成功，则改为`处理中`状态，如果机构返回未成功或者有其他异常，则保持`未提交`状态
7. 对于`处理中`状态的数据，会进入`授信结果查询流程`，对于保持`未提交`状态的数据，会在下次处理时重试

授信结果查询流程：
1. ice-pfs-app 定时查询数据库中状态为`处理中`的记录，并对每一笔授信都调用ice-partner-app提供的queryCreditResult接口(dubbo接口)
2. ice-partner-app 收到ice-pfs-app调用后，会将请求原样转发到ice-gws-app的queryCreditResult接口(dubbo接口)
3. ice-gws-app 收到ice-partner-app调用后，会将请求参数加密加签，并调用机构提供的queryCreditResult接口(http接口)
4. ice-gws-app收到机构响应后，解密机构的响应内容，并返回到ice-partner-app
5. ice-partner-app再将响应返回给ice-pfs-app
6. ice-pfs-app根据机构响应的状态调整数据库中授信记录的状态，机构可能会返回授信成功、授信失败、处理中，相应把数据改为`授信成功`，`授信失败`，保持`处理中`
 - 对于`授信成功`的记录，会向用户发授信成功短信，并将授信额度合同推送到ice-core-app中维护
 - 对于`授信失败`的记录，会向用户发授信失败短信
 - 对于`处理中`的记录，会等待下次重试查询

授信结果通知流程：除了ice-pfs-app会定时主动查询用户授信的结果外，当机构授信出结果后，也可以主动推送结果给智信，推送流程如下：
1. 机构调用ice-gws-app-web的授信结果通知接口noticeCreditResult（http接口），请求参数中包含所有授信结果的信息，ice-gws-web会将请求参数验签解密，并将解密后的参数请求转发给ice-pfs-app
2. ice-pfs-app根据机构提交过来的状态调整授信记录状态（与查询结果流程中的调整方式一致

# 借款流程

## 用户借款申请流程

用户登录APP ➔ 路由系统(ice-crp-app)推荐机构 ➔ 用户借款试算 ➔ 同意协议和还款计划 ➔ 绑定银行卡(可选) ➔ 人脸验证(可选) ➔ 提交申请到ice-pfs-app

借款试算：
1. 指的是用户在借款前先算出用户的还款计划信息，让用户知道自己每一期的还款时间、还款本金、还款利息
2. 借款试算调用的是机构的借款试算接口(loanTrial)，触发流程大概是：ice-pfs-app ➔ ice-partner-app ➔ ice-gws-app ➔ 机构
3. 机构返回的loanTrial的响应中包含还款计划信息、协议信息等，用于下一步`同意协议和还款计划`
4. 用户申请提交到ice-pfs-app后，与授信类似，ice-pfs-app会有`借款提交流程`和`借款结果查询流程`

借款提交流程：指的是将用户的借款请求提交给机构，请求的流程如下：
1. ice-pfs-app轮询所有未提交状态的数据 ➔ ice-partner-app(applyLoan接口 dubbo) ➔ ice-gws-app(applyLoan接口 dubbo) ➔ 机构(applyLoan接口 http)
2. ice-pfs-app中同样会根据机构的返回值更新内部借款记录的状态，返回接收成功 => 更新为处理中，其他情况 => 保持未提交状态

借款结果查询流程：对于借款提交成功的借据，进入借款结果查询流程，目的是获取借款结果：
1. ice-pfs-app轮询所有处理中状态的数据 ➔ ice-partner-app(queryLoanResult接口dubbo) ➔ ice-gws-app(queryLoanResult接口dubbo) ➔ 机构(queryLoanResult接口 http)
2. ice-pfs-app中同样会根据机构的返回值更新内部借款记录的状态，更新为成功、失败、或保持处理中
 - 对于借款成功的数据，发送借款成功短信，并将借据和还款计划信息推送到ice-core-app维护
 - 对于借款失败的数据，发送借款失败短信

借款结果通知流程：对于借款提交成功的借据，机构也可以主动调用智信提供的借款结果通知接口告知借款结果
1. 机构 ➔ ice-gws-web(noticeLoanResult http接口) ➔ ice-pfs-app
2. ice-pfs-app中同样会根据机构的借款结果信息更新内部借款记录的状态
 - 对于借款成功的数据，发送借款成功短信，并将借据和还款计划信息推送到ice-core-app维护
 - 对于借款失败的数据，发送借款失败短信

# 还款流程

## 用户还款流程

1. 用户主动登录APP查看信息的借据详情页
2. 用户点击还款按钮，发起还款试算
3. 页面展示还款试算结果，包含用户需还款的金额及其明细（如本金、利息等）
4. 用户选择银行卡，也可以绑定新的银行卡提交还款
5. ice-pfs-app调用ice-core-app的还款申请接口提交用户还款

还款试算：
 - 指的是用户在确认还款前，系统先为用户算出本次需要还多少钱，其中包含本金、利息、罚息等费用项各多少
 - 还款试算请求流程：ice-pfs-app ➔ ice-core-app（repayTrial接口dubbo） ➔ ice-partner-app（loanTrial接口dubbo） ➔ ice-gws-app（loanTrial接口dubbo） ➔ 机构（loanTrial接口http）

## 系统批扣流程

1. 对于辅助扣款模式机构，当用户的借据到期或者逾期后，ice-core-app会在每天7，15，20点给用户触发批扣
2. 批扣相当于系统主动为用户发起还款申请，默认使用用户上次的还款卡。但是不会触发还款试算，而是直接提交
3. 对于普通机构扣款模式的机构，智信不会主动发起批扣，而是由机构自行批扣，参考下面的`机构批扣流程`

批扣：即批量扣款，指的是系统自动对逾期或到期的借据发起扣款的行为

## 还款处理流程

不论是用户主动发起的还款还是系统批扣的还款，都会进入到还款处理流程，包含以下几个部分：

1. 还款提交机构流程：
 - ice-core-app收到ice-pfs-app的还款申请调用或者在批扣时，都会在还款表落一条记录，并把还款信息推送到`还款申请消息队列`
 - ice-core-app自行消费还款申请消息队列数据，对于里面的每笔数据都执行以下操作
	 - ice-core-app调用ice-partner-app的applyRepayment接口
	 - ice-partner-app会根据机构的绑卡扣款类型判断：
		- 如果是辅助扣款模式，ice-partner-app会调用pcs做支付路由，路由出扣款需要的支付协议号，并补充在请求参数中，然后调用ice-gws-app的applyRepayment接口
		- 如果是机构绑卡扣款模式，ice-partner-app会直接将请求转发给ice-gws-app的applyRepayment
	 - ice-gws-app调用机构的applyRepayment接口（http接口，加密调用） 并解密机构的响应参数后返回给ice-partner-app
	 - ice-partner-app再将响应返回给ice-core-app，ice-core-app根据机构的响应状态做以下处理：
		- 如果机构返回接收成功，则状态流转到`处理中`；
		- 其他情况下将还款状态流转到`申请失败`状态

2. 机构扣款：
 - 机构收到还款申请后，会调用支付渠道的接口扣用户的款
 - 如果是辅助扣款模式，则会使用请求参数中支付协议号扣款。如果是普通机构扣款模式，则机构内部会自行维护支付协议号，因此会自行查找协议号扣款

3. 还款查询流程：
 - 还款进入到处理中状态后，ice-core-app会定时查询这个状态的数据，并对每一条记录都执行以下步骤：
	- 调用机构的还款结果查询接口(queryRepayResult)，调用链路为：ice-core-app ➔ ice-partner-app ➔ ice-gws-app ➔ 机构
	- 根据机构返回的状态 成功/处理中/失败，将还款状态更新成`还款成功`/`处理中`/`还款失败`
		- 对于还款成功的数据，更新用户的还款计划和借据信息（机构返回的结果中会包含还款成功后的借据与还款计划信息），并发送还款成功短信
		- 对于还款失败的数据，发送还款失败的短信

4. 还款通知流程
 - 机构给用户扣款成功/失败后，也可以主动调用智信提供的noticeRepayment接口通知还款状态
 - 调用链路：机构 ➔ ice-gws-web ➔ ice-core-app
 - 根据机构返回的状态S/F=成功/失败，将还款状态更新成`还款成功`/`还款失败`
	- 对于还款成功的数据，更新用户的还款计划和借据信息（机构还款结果里会带上还款成功后的还款计划的借据信息），并发送还款成功短信
	- 对于还款失败的数据，发送还款失败的短信

5. 还款补处理流程：
 - 对于`还款提交机构流程`中，流转到`申请失败`状态的数据，会进入到还款补处理流程中
 - 在该流程中，会定时轮询所有`申请失败`的数据，并对每笔数据调用`还款查询流程`，根据机构返回的还款状态：
	- 机构返回处理中：则将还款状态流转到处理中状态
	- 机构返回掉单：则将还款状态置为还款失败。所谓掉单是一种特殊的状态，指的是机构没有收到这笔还款请求
	- 机构返回还款成功：则更新用户的还款计划和借据信息，并发送还款成功短信
	- 机构返回还款失败：发送还款失败的短信

## 机构批扣流程
 - 对于机构绑卡扣款模式的机构，当用户的借据到期或逾期后，机构会每天定时给用户发起批扣，这种情况下机构在批扣成功/失败后直接调用还款结果通知接口告诉智信批扣结果即可，无需还款试算，还款申请，还款结果查询接口的交互
 - 对于批扣成功的数据：更新用户的还款计划和借据信息，给用户发送还款成功短信，并记录还款记录
 - 对于批扣失败的数据：智信仅发送还款失败短信，不落还款记录

# 信息同步流程

## 额度信息同步流程

智信内部会缓存机构给用户的额度信息，并在以下时机调用机构的额度查询接口（queryCreditProduct）更新数据:
 - 用户登录APP时，该流程每12小时对于每笔授信额度仅触发一次
 - 用户借款成功后，不限频率
 - 用户还款成功后，不限频率

同时，如果机构给用户做了提额，也可以做额度通知(changeCreditProduct)给智信，智信会实时更新用户额度信息

## 借据还款计划信息同步流程

智信内部会缓存机构给用户的借据和还款计划信息，并在以下时机调用机构的借据&还款计划查询接口（queryLoanPlan）更新数据：
 - 用户登录APP时，该流程每12小时对于每笔借据仅触发一次
 - 用户还款成功后，不限频率
 - 用户借据到期或逾期后，每天凌晨会自动同步
 
 注意的是，借据还款计划没有对应的通知接口
 
 
 
 以上是智信贷款平台的系统架构与核心流程信息
