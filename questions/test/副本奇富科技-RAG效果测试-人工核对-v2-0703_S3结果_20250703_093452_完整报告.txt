问题4: 绑卡时机构扣款模式有何区别？
答案: 根据上下文信息，绑卡时机构扣款模式的主要区别如下：

1. **机构绑卡扣款模式**：
   - 用户绑卡时需要将银行卡绑定到机构平台内部。
   - 绑卡流程需要调用机构的发送验证码接口（`applyCertification`）和校验验证码接口（`verifyCode`）。
   - 调用链路为：`ice-pfs-app` → `ice-partner-app` → `ice-gws-app` → 机构HTTP接口。
   - 后续还款时由机构自行扣款，智信无需处理支付协议号。
   - 机构在批扣成功/失败后直接调用还款结果通知接口告知智信结果（参考文档4）。

2. **辅助扣款模式**：
   - 用户绑卡时将银行卡绑定到借条内部，而非机构平台。
   - 绑卡时不需要调用机构的接口，而是调用智信的支付统一处理服务（PCS）接口。
   - 后续还款时由智信负责选择扣款渠道及协议号，并在还款申请接口中传给机构，机构使用该协议号扣款（参考文档1和文档6）。
   - 智信会在每天固定时间（7点、15点、20点）主动触发批扣（参考文档5）。

**关键区别总结**：
- **绑卡目标**：机构绑卡模式绑定到机构平台，辅助模式绑定到借条。
- **接口调用**：机构绑卡模式需调用机构验证接口，辅助模式调用PCS接口。
- **扣款责任**：机构绑卡模式由机构自行扣款，辅助模式由智信提供协议号并协调扣款。

（信息来源：文档1、文档4、文档5、文档6）

问题5: 授信结果通知接口如何触发？
答案: 授信结果通知接口的触发方式如下：

1. **主动触发机制**：
   - 当授信机构完成授信审批后（达到终态：成功/失败/拒绝等），机构会**主动调用**智信系统的`ice-gws-app-web`提供的`noticeCreditResult`接口（HTTP接口）推送结果（文档1授信结果通知流程第1步）。

2. **触发条件**：
   - 仅当授信状态为终态时触发（如文档2场景说明所述："授信已终态（明确成功，失败）情况下，发送通知"）。状态包括：
     - `S`（授信成功）
     - `F`（申请失败）
     - `R`（授信拒绝）
     - `C`（取消）
   - 处理中状态（`P`）不会触发通知（文档2状态字段说明）。

3. **接口处理流程**：
   - 机构调用后，`ice-gws-app-web`会验签解密请求参数，并转发给`ice-pfs-app`更新数据库状态（文档1第2步）。
   - `ice-pfs-app`根据状态执行后续操作（如发送短信、推送额度合同等，与查询结果流程一致）。

**补充说明**：该通知接口是**对定时查询的补充机制**，机构可选择主动推送终态结果以加速流程，但系统仍会通过定时查询确保状态同步（文档1提到两种方式并存）。

问题7: 借款失败后系统如何重试？
答案: 根据上下文信息，借款失败后的重试机制如下：

1. **借款申请接口(applyLoan)失败时**：
   - 当applyResult=F时（文档2），智信系统会先调用借款结果查询接口(queryLoanResult)确认是否掉单
   - 如果查询到掉单（即queryLoanResult返回applyResult=U），系统会重发借款申请（文档1常见问题a点）

2. **借款结果查询接口(queryLoanResult)失败时**：
   - 当applyResult=U（申请号不存在/掉单）时，系统会认为掉单并重试借款申请（文档1常见问题a点）
   - 当applyResult=S且loanStatus=F时，系统会直接终止流程，不会重试（文档1常见问题b点）
   - 当applyResult=S且loanStatus=P时，系统会在1分钟后再次查询结果（文档1常见问题c点）

3. **整体流程**（文档3补充）：
   - 借款提交流程失败会保持"未提交"状态继续轮询重试
   - 借款结果查询流程中，只有处理中状态(P)会持续轮询，失败状态(F)会终止流程

注意：系统不会对明确返回loanStatus=F的最终失败结果进行重试，仅对掉单(U)或处理中(P)状态进行重试操作。

问题9: 系统批扣和机构批扣有何差异？
答案: 系统批扣和机构批扣的主要差异如下：

1. **发起主体不同**  
   - 系统批扣：由智信系统（ice-core-app）主动发起，适用于辅助扣款模式的机构。  
   - 机构批扣：由合作机构自行发起，适用于绑卡扣款模式的机构。  

2. **触发时间不同**  
   - 系统批扣：每天固定时间（7点、15点、20点）触发。  
   - 机构批扣：由机构自行设定批扣时间（文档未明确具体时间）。  

3. **交互流程不同**  
   - 系统批扣：直接使用用户上次的还款卡扣款，跳过还款试算等步骤。  
   - 机构批扣：机构扣款后仅需通知智信结果，无需与还款试算、申请等接口交互。  

4. **结果处理差异**  
   - 共同点：两者均会发送还款成功/失败短信。  
   - 不同点：  
     - 系统批扣未明确说明失败时的数据记录（文档1未提及）。  
     - 机构批扣失败时，智信不记录还款数据（文档2明确说明）。  

**总结**：核心区别在于发起主体和流程简化程度，机构批扣由外部主导且交互更简单，系统批扣则由智信内部自动化处理。

问题18: 链接安全性方案如何验证token？
答案: 根据上下文信息，链接安全性方案验证token的步骤如下：

1. **获取token**：360会在链接上添加token（例如iceToken），合作方需要从链接中提取该token参数。

2. **解密token**：
   - 使用预设的AES密钥（如示例中的`aaaabbbbccccdddd`，Base64编码为`YWFhYWJiYmJjY2NjZGRkZA==`）对token进行解密。
   - 示例中加密后的token为`bJt1E0SiSwppWumECMtFqBd7qQ1FZiKUE3OveuoshIc=`，解密后可得到原始信息（如`userId=PUR000001, timestamp=1669023661765`）。

3. **验证token内容**：
   - 检查解密后的信息是否符合预期格式（如包含有效的`userId`和`timestamp`）。
   - 验证时间戳（`timestamp`）是否在有效期内，防止重放攻击。

4. **拼接链接示例**：
   - 原始链接：`http://localhost:8096/ag?xxx=abc#users`
   - 拼接token后：`http://localhost:8096/ag?xxx=abc&iceToken=bJt1E0SiSwppWumECMtFqBd7qQ1FZiKUE3OveuoshIc=#users`  
   （需根据实际链接结构调整参数位置）

**关键点**：  
- 双方需提前约定加密方式（AES）、密钥及token名称（如`iceToken`）。  
- 合作方需实现相同的AES解密逻辑以验证token有效性。

问题20: 用户主动还款失败后如何重试？
答案: 根据上下文信息，用户主动还款失败后的重试机制主要通过以下流程实现（综合文档2和文档3）：

1. **还款补处理流程**（文档2第5部分）：
   - 当还款在"还款提交机构流程"中失败（状态为"申请失败"）时，系统会自动进入补处理流程
   - 系统会定时轮询所有"申请失败"的还款记录
   - 对每笔失败记录调用`queryRepayResult`接口（文档3）查询机构端的实际状态

2. **重试处理逻辑**：
   - 如果机构返回"处理中"（P），状态转为"处理中"继续等待
   - 如果机构返回"掉单"（U），标记为最终失败
   - 如果机构返回"成功"（S），更新还款计划和借据信息
   - 如果机构返回"失败"（F），发送失败通知

3. **主动通知机制**（文档2第4部分）：
   - 机构也可通过调用`noticeRepayment`接口主动通知还款结果
   - 智信引擎会根据通知更新还款状态

4. **用户侧操作**：
   - 文档未明确说明用户是否可以手动重试
   - 系统会自动进行重试查询，无需用户主动操作

注意：所有重试操作都是系统自动完成的，用户只需等待系统处理结果通知。如果最终失败，可能需要用户检查失败原因后重新发起还款申请。
